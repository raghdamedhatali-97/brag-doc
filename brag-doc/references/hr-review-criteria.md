# HR review criteria

Use these rules to write weekly updates and the quarterly, H1 and year-end self-assessment. They follow common HR guidance for self-evaluations (STAR structure, quantified impact, links to objectives, balance) and the brag document method popularised by Julia Evans.

## 1. Lead with results, not activity

Weak: "Worked on the month-end close process."
Strong: "Cut month-end close from 8 to 5 working days by automating 3 reconciliations."

Each achievement starts with the result, then how.

## 2. Use STAR for every key achievement

| Part | Question | Length |
|---|---|---|
| **Situation** | What was the context or problem? | 1 short clause |
| **Task** | What was your responsibility? | 1 short clause |
| **Action** | What did *you* do? Use "I", not "we", for your part. | 1 sentence |
| **Result** | What changed, with a number where possible? | 1 sentence |

In the document, show the Result first in bold, then Situation, Task and Action in one plain sentence.

## 3. Quantify impact

- Target: at least 70% of achievements carry a number (%, SAR or other currency, hours, days, count, rank).
- Use the user's own numbers from entries. Never invent, round up or estimate.
- If no number exists, keep the claim qualitative and specific ("the CFO used the analysis to approve the new pricing"), or mark `[add number]` for the user to fill in.
- Before and after beats a single number: "from 3 days to 1" is stronger than "saved 2 days".

## 4. Link everything to objectives

- Group achievements under the objective they support (`O1`, `O2`, ...), using the objective titles exactly as the company wrote them.
- For each objective, state the status in plain words: Achieved, On track, At risk, or Not started. Base it on the entries. If unclear, ask the user.
- If an objective has no evidence in the period, say so honestly and ask the user whether there is work they forgot to log.

## 5. Show the extra mile

Extra mile = valuable work outside the objectives: cross-team help, unrequested improvements, mentoring, representing the team, ideas adopted. Give each item a title, what you did and the result. Do not pad this section with routine duties.

## 6. Name stakeholders

List the key people or teams worked with and on what. This shows reach and influence. Roles are fine if the user prefers not to name people.

## 7. Be honest and balanced

- "Make it sound exactly as good as it is." (Julia Evans)
- Include one genuine development area with what the user is doing about it. This shows self-awareness, which reviewers value.
- No hype words unless the user used them: spearheaded, synergy, game-changing, rockstar, passionate, leveraged, world-class, revolutionised.
- Prefer plain verbs: built, cut, fixed, launched, led, reduced, trained, negotiated, automated, delivered.

## 8. Keep it scannable

- Summary: 3-4 sentences.
- Each objective: 2-3 strongest achievements, not everything.
- KPI tiles: up to 4 headline numbers.
- Total length: 2-4 pages. A manager should grasp the story in 2 minutes.

## 9. Weekly update rules

- Under 200 words.
- Top 3 wins, each with impact.
- One line per objective with movement this week.
- "Where I need help": blockers the manager can clear. Omit if none.
- Next week's focus: 2-3 bullets.
